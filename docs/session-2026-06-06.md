## GPU Inference Refactor — completed this session

Self-play training was running at 164 FPS with one checkpoint in the pool (CPU inference inside subprocesses). Built a centralized GPU inference server to fix this.

### Architecture (`training/inference_server.py`, new file)

- `InferenceServer`: daemon thread in main process; one `multiprocessing.Pipe(duplex=True)` per env; `{path: MaskablePPO}` dict of models on GPU; `connection.wait()` batches requests; groups by path; one `predict()` per distinct model; crash-safe with fallback actions
- `InferenceHandle`: picklable proxy with the client-side `Connection`; subprocess calls `handle.request(path, obs, mask)`
- `_CheckpointAgent`: uses handle if present, CPU fallback if not
- `update_model(path)`: 13s load OUTSIDE lock, atomic swap inside
- `CheckpointCallback`: calls `update_model()` after each save

### Critical gotcha: start_method='fork'

SB3 uses **forkserver** by default. cloudpickle (used to serialize env closures) does NOT properly transfer `multiprocessing.Connection` FDs → `OSError: [Errno 9] Bad file descriptor` in subprocess.

Fix: `SubprocVecEnv(env_fns, start_method='fork')` when inference_server is active. Subprocesses never call CUDA so fork+CUDA-in-parent is safe.

### Result

- Before: ~164 FPS (1 checkpoint in pool)
- After: ~1440 FPS (8.8× speedup, matching threshold-only baseline)

## Phase 2 collapse — second occurrence

Started selfplay Phase 2 again (from 5.6M checkpoint, threshold_mix=0.5). Collapsed again:

| Step | entropy_loss | ep_rew_mean | ep_len_mean | FPS |
|---|---|---|---|---|
| 5.6M (start) | -0.14 | ~0.4 | ~2 | 1440 |
| 6.47M | -0.027 | 0.197 | ~2 | 1330 |
| 6.6M+ | ~0 | -7.28 | 165 | 711 |

- Entropy went to near-zero very fast (~900k steps)
- Episodes ballooned from 2 turns to 165 turns (agent stuck in a loop)
- ep_rew_mean → -7.28 (losing badly)
- Same pattern as the April collapse (selfplay_final → 56% vs Threshold)

Training killed at ~6.6M steps. Saved checkpoints: `6100000.zip`, `6600000.zip`.

**Root cause hypothesis:** With `threshold_mix=0.5`, the 50% checkpoint opponents all use the SAME latest checkpoint (as picked up by the glob). The agent quickly learns to exploit that fixed opponent deterministically, gaining reward by playing one strategy. This strategy is internally consistent (agent beats itself) but plays randomly/badly against the Threshold anchor. As the policy entropy collapses, the Threshold anchor opponents (50%) yield very negative rewards, which now dominate.
